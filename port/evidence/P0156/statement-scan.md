# P0156 statement compatibility scan

The 99-file target-and-dependency closure contains no uses of `IsLattice` or
`IsMulTorsionFree`. It has two theorem assumptions using `IsAddTorsionFree`, both
in M157820, `Formalism.PieriBlockIdeals.PieriColumnMinors.HeightDescentMinors`:

- `eq_zero_of_binomial_ode`
- `eq_of_binomial_ode_of_constantCoeff_eq`

Both theorems have the existing assumption `[CommRing R]`. At the replay Mathlib
pin `0df444a360eaa60ab8c11dca51a86af692955474`, `IsAddTorsionFree R` requires
injectivity of natural scalar multiplication `n • x` for every `n ≠ 0`. At the port pin
`fc4f59e577feb1a4956671bc04ac18aaaf8cd842`, the class requires injectivity on
commuting additive elements. These conditions are equivalent for a commutative
ring because every pair of additive elements commutes. The target Mathlib lemma
`IsAddTorsionFree.hasUniqueDiv` supplies the unconditional injectivity property
under an additive commutativity assumption. Conversely, unconditional
injectivity immediately gives injectivity on commuting elements.

Relevant source files:

- Replay pin: [Mathlib/Algebra/Group/Defs.lean](https://github.com/leanprover-community/mathlib4/blob/0df444a360eaa60ab8c11dca51a86af692955474/Mathlib/Algebra/Group/Defs.lean), class `IsAddTorsionFree`.
- Port pin: [Mathlib/Algebra/Group/Monoid.lean](https://github.com/leanprover-community/mathlib4/blob/fc4f59e577feb1a4956671bc04ac18aaaf8cd842/Mathlib/Algebra/Group/Monoid.lean), classes `IsAddTorsionFree` and
  `HasUniqueDiv`.
- Port pin: [Mathlib/Algebra/Group/Torsion.lean](https://github.com/leanprover-community/mathlib4/blob/fc4f59e577feb1a4956671bc04ac18aaaf8cd842/Mathlib/Algebra/Group/Torsion.lean), lemma
  `IsAddTorsionFree.hasUniqueDiv` (generated by `to_additive` from
  `IsMulTorsionFree.hasUniqueRoots`).

## Formal derivative parameter

M157820 uses the old application `d⁄dX R` thirteen times. At the replay pin,
`PowerSeries.derivative` makes its coefficient ring `R` an explicit parameter.
At the port pin, `R` is implicit. The equivalent target application is
`d⁄dX f`, with `R` inferred from the unchanged type `R⟦X⟧` of `f`.
Both declarations define the same formal derivative from
`MvPowerSeries.pderiv` at the unique variable `()`, on the same coefficient ring.
The coefficient identity remains
`coeff n (d⁄dX f) = coeff (n + 1) f * (n + 1)`.

This spelling change occurs in the statements of
`coeff_one_add_X_mul_derivative`, `eq_zero_of_binomial_ode`,
`eq_of_binomial_ode_of_constantCoeff_eq`, and
`binomialSeries_one_add_X_mul_derivative`, and in proof terms. It changes only
how the existing coefficient ring argument is supplied; the assumptions and
mathematical propositions are preserved.

The local binomial-ring instance is registered through
`BinomialRing.toHasUniqueDiv`, the current projection. Its deprecated
`toIsAddTorsionFree` alias has generalized parameters that fail the target
instance synthesization-order check when registered as an instance. This
registration change selects the same projection and does not alter a theorem
statement or supply an additional assumption.

- Replay declaration: [Mathlib/RingTheory/PowerSeries/Derivative.lean](https://github.com/leanprover-community/mathlib4/blob/0df444a360eaa60ab8c11dca51a86af692955474/Mathlib/RingTheory/PowerSeries/Derivative.lean).

## Natural valuation proof API

M157829 changes only the proof of `label_vl_le_one`. It uses
`pow_multiplicity_dvd` and the target theorem `Nat.padicValNat_def` to rewrite
the natural valuation to the equal multiplicity expression. The same equality
is included when simplifying `padicValInt`. The declaration statement,
quantifiers, assumptions, and definitions are unchanged.

The two affected proof steps compile in a narrow target-toolchain probe. That
probe does not replace the required full-module build.

- Target valuation equality: [Mathlib/Data/Nat/PadicValNat.lean](https://github.com/leanprover-community/mathlib4/blob/fc4f59e577feb1a4956671bc04ac18aaaf8cd842/Mathlib/Data/Nat/PadicValNat.lean).
- Target divisibility theorem: [Mathlib/RingTheory/Multiplicity.lean](https://github.com/leanprover-community/mathlib4/blob/fc4f59e577feb1a4956671bc04ac18aaaf8cd842/Mathlib/RingTheory/Multiplicity.lean).

M157898 and M158068 make the same proof-only valuation API migration.
`Nat.padicValNat_def` is an equality, so changing a proof's intermediate
expression from `padicValNat p n` to `multiplicity p n` changes neither the
valuation nor its argument. The product and prime-power identities use the
existing nonzero and prime hypotheses. Every declaration statement and
definition in these two modules is unchanged.

## Multivariate polynomial coefficients

M157895 and M157908 replace the old accessor spelling `coeff e p` with
`p.coeff e`. At the replay Mathlib pin, `MvPolynomial.coeff` had this body:

```lean
@DFunLike.coe ((σ →₀ ℕ) →₀ R) _ _ _ (AddMonoidAlgebra.coeff p) e
```

The target field accessor `p.coeff e` is definitionally this same application.
`MvPolynomial σ R` remains `AddMonoidAlgebra R (σ →₀ ℕ)`. A target-toolchain
compatibility probe proves equality between the exact old body and the target
accessor by `rfl`.

In M157895, the spelling changes affect the two statements
`coeff_diagMul_pow` and `coeff_diagLaplacian_pow`, plus proof expressions.
In M157908, they affect `coeff_X_mul_pderiv`, `coeff_eulX`, and `coeff_eulY`.
The coefficient indices, polynomial operands, quantifiers, hypotheses, and
mathematical propositions are unchanged. No definitions or instances change.
M157895 also qualifies the same addition identity as
`MvPolynomial.coeff_add`, since that declaration is now protected.

- Replay coefficient definition: [Mathlib/Algebra/MvPolynomial/Basic.lean](https://github.com/leanprover-community/mathlib4/blob/0df444a360eaa60ab8c11dca51a86af692955474/Mathlib/Algebra/MvPolynomial/Basic.lean).
- Target polynomial abbreviation and coefficient identities: [Mathlib/Algebra/MvPolynomial/Basic.lean](https://github.com/leanprover-community/mathlib4/blob/fc4f59e577feb1a4956671bc04ac18aaaf8cd842/Mathlib/Algebra/MvPolynomial/Basic.lean).
